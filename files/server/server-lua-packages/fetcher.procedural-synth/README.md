# FETCHER STUDIO

This optional package supplies a native, spatial, multiplayer subtractive synthesizer, its in-game sound editor, MIDI mixer, piano clips, drum machine and personal presets/projects. It does not require Bardcraft scripts, a client ESP, prerecorded samples or an external synthesis library.

Current source: package 33 / native synth API 16 / multiplayer protocol 27.
Studio supports 32 parts, reusable multi-track patterns, subtitle sample search
and independent concurrent playback. These native changes require matching client
and server builds; source completion does not publish a release.
Standing NPC staging and the first orchestral props are available. Next: seated
layouts and conductor presentation. See [the roadmap](ROADMAP.md).

## Standing bands and orchestral instruments

Import or create a song, open **Band**, then choose **Auto NPC band**. The server
hires or reuses one owned NPC per part, up to 32, places a grid ahead of the
leader, and turns each performer toward the captured leader position. Use clear,
level ground with enough room: the grid does not yet detect floors or obstacles.
NPCs remain standing when playback stops. Walking away does not move the stage;
**Restage grid** explicitly moves the bound formation. Routing is one Undo action;
Undo does not dismiss hired NPCs. Members and tracks have separate eight-row pages.

Click a part in Band and use its instrument selector to choose keyboard, lute,
drum, violin, cello, trumpet, flute, clarinet or timpani. The physical model is
saved separately from its sound. MIDI programs choose initial props; saved choices
take precedence. **Orchestra** is a whole-song sound set, and **Orchestral / Cinematic**
contains six editable synthesized starting patches. These approximate acoustic
instruments; they are not orchestral sample libraries. F9 exposes the same nine
held-instrument choices for player performers.

The keyboard uses the combined Yamaha and X-stand model, anchored to the floor.
Lute fretting/strumming, keyboard presses, alternating drum/mallet strikes,
bow strokes and wind finger motions have separate arm/wrist/finger profiles.
Violin/cello include bows; timpani includes two mallets. The cello currently uses
a provisional standing stance. Chairs, music stands, further instrument families
and large-ensemble listening/performance refinement remain on the roadmap.

Install the complete optional asset bundle on each client. The original orchestral
props, textures and inventory icons are generated by
`scripts/procedural-synth-assets/generate_orchestra.py`; their notice and the
existing Sketchfab model credits are retained in `ATTRIBUTION.txt`. The six new
inventory records use IDs `fetcher_studio_<instrument>_v1`. Missing models are
reported in Band; playback remains available with a fallback prop. The matching
native client updates moving attachments without recreating their meshes each frame.

powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-procedural-synth-test.ps1

The existing root test binaries, Mario/Sith Soldier profiles, Starwind content configuration and original test database are preserved.

Stop fixture processes before rerunning setup.

Finally Synth A holds note 76 and logs `READY abrupt disconnect`; terminate only that fixture client to exercise observer takeover. The editor also has MIDI previous/next, **Play MIDI** and **Stop** controls. Setup copies the locally installed Bardcraft MIDI directory into an isolated data directory; it copies no Bardcraft ESP, scripts or samples. Override its source with `-BardcraftDataDirectory 'C:\path\to\Bardcraft'`. Other installations can supply their own `.mid`/`.midi` files under a configured data directory's `midi/` folder. Files are discovered on the first frame even when resuming a saved multiplayer character. Original mod/song files are preserved and are not redistributed by this repository.

Format 0/1 MIDI with PPQ timing supports merged tracks, tempo changes, running status, velocity, sustain pedal and note cleanup. Imports retain SMF track names, channels, program metadata and tempo maps. Each (SMF track, MIDI channel) becomes an independently assignable part; channel-10 percussion is split further by pitch, with kick/snare/hat synth defaults. Program changes, pitch bend and expression/volume controllers do not alter the assigned sound. Imports exceeding 32 parts including existing clips are rejected explicitly. Imports are limited to 512 KiB, 64 tracks, 60,000 retained events and 30 minutes; parsing yields between bounded groups of operations. Playback stops on long frame stalls or excessive density instead of bursting stale notes into the server. Manual playing, preset loads, Stop, Finish, disconnect and session loss release playback. MIDI notes use the same validated note transport and 3D synth as live playing, rather than transferring audio or MIDI files to listeners.

During a session both clients pose the authenticated performer's upper arms, forearms and hands toward the instrument. Two-link IK preserves arm lengths and clamps unreachable targets; live notes add small wrist/target pulses. This first pass does not animate keyboard keys or fingers. The default test asset combines a wider Yamaha keyboard and X-stand, with the keys approximately 89 units above its floor origin. Hand contact and posture still require visual tuning for different races and positions; unreachable targets cannot be reached by stretching the skeleton. The pose does not move or turn the actor. Finish or session cleanup restores normal animation, with a native half-second expiry as backup.

Use `-MidiProbe` for the disposable two-client Greensleeves/arm-pose test. It implies `-LiveProbe`; setup without either flag restores interactive mode.

## Studio workflow

Both views share a local window toolbar. Drag **Drag to move**, resize with the
bottom-right mint grip, and use **Scale - / +** to change text and control sizes
(75-200%, bounded to fit the current viewport). **Fullscreen / Restore** toggles
an in-game full-viewport view and restores the previous window geometry. Window
position, size, scale and fullscreen preference are saved in local player Lua
storage and survive view switches and reopening; they are not sent to the server.

**Monitor Volume (local)** controls the same **Player Instruments** category as
Options > Sound. It affects every procedural instrument you hear, including other
players, independently of Effects and background Music. Game Master still applies.
The Studio Master and track faders remain the shared project mix; monitoring does
not modify presets, projects or other listeners. Native `openmw.synth` version 3
provides `getMonitorVolume()` and `setMonitorVolume(0..1)`; setters validate finite
values and apply to already-playing streams on the engine thread.

The bar-count dropdown selects from 1 through 16 bars. It changes playback length
without deleting later drum steps or piano notes. Each clip retains 256 steps;
hidden bars survive Save/Load and return when the loop grows. Earlier 1-4-bar
projects are padded on load while retaining their existing composition.

Activate the keyboard and click **Studio**. The tabs switch between **Synth**,
**Mixer**, **Piano** and **Drums**, using one window so only one view captures game
input. F8 / Hide / Escape preserves playback and reopens the last view; Finish
releases the instrument and every channel. Cameras remain under normal game control.

1. Choose a local or server-library MIDI from the song dropdown and click **Import**.
   **Play song** uses the whole song and its tempo map. **New song** creates an
   editable document without an imported file; Song sets its bar count and loop.
2. **Mixer** assigns saved sounds/samples, levels, mute/solo, effects and outputs.
   **Duplicate track** copies the selected part's notes, sound, mix and routing.
   Four track-page ranges cover parts 1-32 without shrinking the controls.
3. **Piano** edits imported or authored notes. Click to add, drag to move, drag
   the right edge to resize, or right-click to delete. The dedicated editor
   fullscreen button expands the work area; Escape returns to the Studio page.
4. **Drums** edits 16-step bars, up to 16 bars per pattern. **Duplicate lane**
   copies its settings/hits; **Delete lane** removes it. **Clear bar** clears the
   current bar across drum lanes. **Delete bar** removes that time slice across
   legacy drum/piano patterns and shifts later pattern data left; one bar remains
   as the minimum. These operations support Undo. Authored song/clip notes are
   edited separately in Piano/Arrange.
5. **Play clips** plays piano-roll notes, placed clips and drum hits within the
   selected 1-16-bar pattern length. Editing a specific clip source auditions
   only that source. **Play song** plays the complete arrangement instead.
6. **Arrange -> Capture pattern** (also **Drums -> Arrange pattern**) converts
   the current pattern into one reusable source/placement per populated part,
   retaining each sound/sample and selecting the placements together. Captured
   notes move into those sources once; later authored song notes stay in place.
   Duplicate/move the selected group to repeat a multi-instrument phrase. Song
   length is independent of pattern length and extends when authored placements
   go past its end. Extend shortened patterns before capture if hidden legacy
   hits/notes remain. Arrange fills the available window with explicit zoom.
7. **Samples** searches installed paths and voice-line text using the same
   installed-dialogue and fallback transcript resolver as **/voicelines**.
   Assigning a sample to a drum lane sets its trigger to the sample root for
   original-speed playback; existing deliberately pitched lanes retain their
   saved pitch. **Match root** resets such a lane explicitly.
8. **Recording setup -> Count-in click** defaults on independently of the
   ongoing metronome. Recording settings, including click volume, are local.
9. **Projects / Save / Load** stores named projects and recovery snapshots in
   authenticated per-character server SQLite storage. Sound presets are separate.
   MIDI/sample VFS references are saved, rather than copies of installed audio.

A document supports 32 total parts, including percussion lanes split from MIDI
channel 10. This is separate from MIDI's 16 channels per port: several file tracks
can share a MIDI channel and remain separate Studio parts. Imports over the part
limit fail explicitly. Native Studio lanes have at most eight voices each, while
the manual synth retains its 1-32 voice control. Scores, source notes, arrangement
placements and event density remain bounded; see the later feature sections.

The client has a 128-unit audio resource budget shared by all heard instruments.
Each configured Studio timbre costs one unit, and each Studio output stream costs another;
this is neither a track count nor a polyphony setting. Two complete 32-part
keyboards therefore use 66 units before their manual/monitor instruments or extra
band outputs. CPU demand still depends on simultaneous voices/effects, so the
resource guard does not guarantee every 128-unit workload runs in real time.

Use **-DawProbe** with local setup for the disposable two-client parts/mixer,
hidden playback, drum/piano and server-project round-trip test. It implies the
probe package; setup without probe flags restores normal interaction.

## Files and architecture

* `apps/openmw/mwsound/proceduralsynth.{hpp,cpp}`: standalone DSP/control engine; no Lua, OpenAL, VFS or sample-file dependency.
* `apps/openmw/mwsound/synthdecoder.hpp`: procedural mono PCM decoder for existing OpenAL streaming.
* `apps/openmw/mwsound/{sounddecoder.hpp,openaloutput.cpp,soundmanagerimp.*}` and `apps/openmw/mwbase/soundmanager.hpp`: interactive streaming and spatial source lifecycle.
* `apps/openmw/mwlua/synthbindings.*`, `luabindings.cpp`: the player-context `openmw.synth` API.
* `apps/openmw-server/scripts/procedural_synth{,_schema}.lua`: ownership, validation, relay, runtime activator and persistence.
* This package's `client/{global,player,editor,studio,workstation,midi,window,controls}.lua`: activation, native channel lifecycle, sound/Studio views, transport/clip editing and SMF import. `shared/schema.lua` and `shared/project.lua` are checked against their server copies by tests.
* `scripts/procedural-synth-tests`, `scripts/test_procedural_synth*.lua`, `scripts/setup-procedural-synth-test.ps1` and `scripts/seed-procedural-synth-test.py`: unit tests, client harness and disposable local setup.

DSP is 48 kHz mono, converted to signed 16-bit PCM for OpenAL spatialization. Each voice has two oscillators, amp ADSR, filter ADSR and a resonant low-pass state-variable filter. Sine, additive band-limited triangle, PolyBLEP saw/square and deterministic white noise are supported. A per-voice exponential pitch envelope provides falling kick-drum pitch. Synth Kick, Noise Snare and Closed Hat are native synth presets. There is a shared sine LFO for pitch, filter or amplitude modulation. Continuous values and waveform mixtures are smoothed; output uses a soft limiter. Default polyphony is 16, configurable from 1 to 32, with oldest-voice stealing. There are at most 128 native resource units across the whole client (configured timbres plus spatial streams). Studio parts share output streams and use at most eight voices each; the manual synth retains its 1–32 voice control. Running out of sources stops the transport with a message.

Only OpenAL's existing stream worker renders PCM. Controls use fixed-size command storage (256 commands) and a mutex which the audio reader only tries, never waits on. Overflow clears queued commands and requests voice release. Parameter snapshots and all voice/filter/oscillator storage are bounded. Interactive decoders use three 10 ms queued buffers and a 5 ms worker cadence while active. Ordinary streams retain their six 125 ms buffers and normal 50 ms cadence. No continuous PCM is sent over the network.

SoundManager owns streams attached to world references. They use normal environmental processing, Player Instruments/master volume, fixed musical pitch independent of simulation time, 100-unit reference distance and 3000-unit maximum distance. Cell unload, object deletion/disable, explicit close, ten seconds without native keepalive, sound clear and backend shutdown clean up streams. Lua also drops instances on cell change, invalid references, disconnect and missing server liveness.

## API

Available to player scripts on a compatible binary:

```lua
local synth = require('openmw.synth') -- version == 16, sampleRate == 48000, maxUnits == 128
local instrument = synth.create(worldObject) -- spatial source; throws when unavailable
instrument:set('wave1', 2)           -- false for unknown/out-of-range/nonfinite values
instrument:noteOn(60, 0.8)           -- MIDI pitch 0..127, velocity 0..1
instrument:noteOff(60)
instrument:allNotesOff()             -- envelope release, clears pending notes
instrument:keepAlive()              -- call at least every few seconds while in use
print(instrument.peak, instrument.voices, instrument.closed)
instrument:close()                  -- idempotent; no further playback
```

`synth.parameters[name]` exposes immutable `min`, `max`, `default`, `discrete` metadata. `peak` is generated PCM peak before spatial attenuation, not a microphone or final output meter. The package's optional `I.ProceduralSynth` interface exposes `status`, `noteOn`, `noteOff`, `setParameter`, `presetCommand` and `close` for other client scripts/input methods, subject to an owned editor session. Older clients without native module version 16 show a compatibility message on activation instead of acquiring a lock.

Interface version 4 adds `studio()`, `workstation()`, `importMidi(path)`, `saveProject()` and `loadProject()`, plus per-channel meter/parameter summaries and transport time in `status()`. Version 3 added `hide()` and `show()` and the `status().editorVisible` field; `editing` continues to mean owning the session, including while hidden. `close()` retains its original meaning of stopping playback and releasing ownership. Interface version 2 added `midiSongs()`, `playMidi(catalogPath)` and `stopMidi()`. Native `openmw.animation.boneTransformsVersion == 1` adds `getBoneNames`, `getBoneTransform`, `setBoneTransform` and `clearBoneTransform`; see `files/lua_api/openmw/animation.lua` for coordinate spaces, threading, validation and expiry. Transform reads return the matrix and a rotation-only transform, with an option to exclude scripted offsets for IK. `openmw.mp.getPlayerObject(serverGuid)` resolves the authoritative performer to the correct local/remote model in `onFrame`. These visual APIs are independent of the synthesizer. Older clients with no bone extension can still use the audio/editor, with the pose omitted.

The melodic controls are editable: both oscillator waveforms/levels/tuning/fine tuning, oscillator-2 enable, amplitude ADSR, cutoff/resonance, filter-envelope amount/ADSR, LFO rate/depth/destination, volume, gain, voice limit, pitch-envelope amount and pitch decay. The dark editor includes numeric feedback, amplitude-envelope graph, theoretical oscillator preview, output peak/voice count, and mouse/PC musical input. Graph/meter updates are bounded and do not rebuild the entire editor each frame.

New, Save, Save As, Load, Rename, Delete and Reset are implemented. The arrow controls select a catalog entry; Load applies it. Built-ins are Soft Pad, Plucked String, Retro Lead, Bass, Flute-like, Synth Kick, Noise Snare and Closed Hat and Open Hat. Built-ins are read-only; Save on a built-in creates a personal preset. Each character has up to 32 personal presets, stable monotonic `p:N` identifiers and 64-byte names. Existing data is isolated in the `ProceduralSynth/presets` character-storage namespace. Format version 1 fills absent fields with defaults and refuses unknown future versions without overwriting them.

## Server and protocol

Install the three server Lua files through the existing release-files list and add this package directory to the configured server package root. `server.omwscripts` includes the server script, but it returns an empty module unless `Config.PROCEDURAL_SYNTH_ENABLED = true`; default configuration is disabled. Compatible binaries must already be installed on clients. Generic production placement remains an explicit operator operation, for example the existing admin `/placeat fetcher_procedural_synth_v1 1 100` command. The automatic test placement settings are only generated in the isolated fixture.

Existing reliable custom Lua events carry `Synth_Request` client-to-server and `Synth_Message` server-to-client. A client global activation handler forwards only the synth activator to its player script. Acquisition resolves an actual server-placed mpNum and verifies its record, authoritative cell and distance (300 units). The existing server `Activate` intent hook also recognizes the synth. Sender pid/characterId are supplied by the native authenticated bridge; payloads cannot choose a different owner or storage character.

Every owned session has a server epoch, input sequence, output sequence and preset revision. Requests and nested project documents are whitelisted and bounded; preset fields are whitelisted and finite. Notes have a 40/sec, burst-80 token bucket; full parameter updates are coalesced to 10 Hz by the client and limited to 12/sec, burst 16 by the server. Preset operations, acquisition, sync and heartbeat have separate budgets. Note-off/panic/close bypass the musical bucket; redundant note-offs/panic are discarded so they cannot become an unlimited relay. Queue/rate overflow uses release instead of leaving a partially accepted chord held. The controller plays locally and receives no duplicate note echo. Channel IDs 1–32 identify DAW timbres; channel 0 is the original manual synth. Note ownership is keyed by channel and pitch. Channel parameters/levels precede notes and are included in late-listener snapshots. The original global 40/sec, burst-80 note-on budget is shared across the whole project. Off/panic remain safety operations; stopped/deleted tracks release their sources.

An 8-second lease renewed every 2 seconds, authoritative object/range checks, disconnect and cell-change handlers release ownership. Server liveness reaches listeners every two seconds; silent transport loss expires client audio. Clients in the same or loaded actor cells receive state. Newly relevant listeners get current parameters before future live notes and never receive a historical note-on replay. Notes are intentionally not reconstructed midway through a held chord for a late join.

The older Casio model and its notices remain available as an alternative.

The combined Morrowind NIF is 104 × 30.16 × 111.68 game units, with its origin on the floor, 12,189 visual triangles and seven box colliders (84 triangles). The actual exported NIF was reimported and rendered for inspection. Conversion and packaging commands are documented in `scripts/procedural-synth-assets/README.md`.

## Native drum machine and precise editing

Package version 5 requires native `openmw.synth.version >= 4`. The existing
version-1 preset/project formats remain supported. Missing new sound parameters
receive stable defaults: `drumType = 0` and `ampCurve = 1` retain the melodic
engine. Existing saved drum presets/project snapshots retain their old settings;
reload a built-in drum preset to select the new native drum engine.

In Studio > Drums, **+ Kit** adds Kick, Snare, Closed hat and Open hat as one
undoable edit. Individual lane buttons remain available. Click a lane to audition
and select it, then **Sound** to edit that lane directly. Drum presets select the
dedicated editor automatically; **Drum / Synth** switches engine family. Drum type
values are 0 Synth, 1 Kick, 2 Snare, 3 Closed hat and 4 Open hat.

Native drum voices have fixed tuning in Hz independent of incoming MIDI note,
separate exponential body/noise decays, noise high/low-pass filtering, a pitch
sweep, attack click and saturation. Hats use six inharmonic, band-limited square
oscillators alongside filtered noise; their metallic layer is filtered too. A
closed hat chokes open-hat channels belonging to the same placed instrument on
every listener. Repeated hits can overlap within the track's voice limit.
Drum decays specify time to -60 dB. MIDI note-off leaves a one-shot tail intact;
Stop, panic, session cleanup and source expiry still release it. The server keeps
one pending-release flag for accepted one-shot hits so Stop reaches listeners even
after all MIDI gates have ended; redundant panic remains suppressed.

All 41 native parameters are available across the two sound views. Click a numeric
value and press Enter or leave the field to apply it. Times display and accept
milliseconds by default (150 means 150 ms); explicit `0.15 s` is also accepted.
Frequency accepts Hz or `2 kHz`; percentages accept `75` or `75%`. Invalid/nonfinite
and out-of-range values preserve the previous setting. Time/frequency sliders are
logarithmic. +/- buttons adjust small increments; Shift makes continuous buttons
and slider drags finer. The melodic engine also has an amplitude curve control.
Studio tempo, swing and note-entry velocity use the same numeric controls.

Studio **Undo / Redo** (Ctrl+Z / Ctrl+Y or Ctrl+Shift+Z outside text fields) restores
project edits, including steps, notes, track additions/deletions, kit creation,
loop length, mix and track sound changes. History is local, bounded to 64 edits,
and is not saved or transmitted. Consecutive edits to one continuous value are
coalesced within 400 ms. Undo/redo stops playback and marks the restored document
as a new unsaved edit; loading a saved project starts fresh history. Standalone
manual-synth edits outside a project do not have project history.

Use setup **-DrumProbe** for the disposable two-client drum/history/choke/Stop and
SQLite round-trip test. It leaves Studio open for interface inspection. Setup
without probe flags restores interactive operation. The native DSP test accepts
`--preview <path.wav>` to render a normalized eight-second drum audition and beat
without the game; this is a test helper, not Studio WAV export.

Audio-clock scheduling, arrangement, recording, sampling, mixer effects and export
remain subsequent milestones. This change does not claim sample-accurate timing
or acoustic-drum realism.


## Native guitar/effects and starter banks (API 5, package 6)

The sound path now has a reusable native per-instrument insert after voice
summing and before instrument/channel level, the existing protective limiter and
OpenAL positioning. Manual playing and every Studio track use independent inserts.
Overdrive, hard distortion and asymmetric fuzz use 4x FIR interpolation/decimation;
continuous settings and mode transitions are smoothed. Amp Tone supplies three
broad bands; Speaker supplies small/open/dark bandwidth models. These are simple
speaker filters, not cabinet impulse responses or replicas of branded amps.

A noise-excited fractional-delay Karplus-Strong string supplies the guitar source.
String decay, damping, palm mute and pick position shape the pluck. Picking velocity
also affects brightness. This is a basic physical string model; recorded guitar
articulations, strumming input, bends/slides and external audio input remain future
work. Its delay storage is preallocated (1 MiB per native instance); rendering and
plucking allocate no memory. Active inserts introduce 16 samples of FIR delay,
with a matching delayed dry signal. The original bypass path has no added delay.

Open Synth or a track's Sound editor, then choose **Browse**. **Bank >** cycles
All, Guitar, genre groups and Personal. Select a sound, then **Load + Audition**
to apply it and play a short note. This replaces that instrument's working sound;
Studio Undo restores its previous patch. Use **Effects** for drive/tone/mix/output,
amp EQ and speaker settings. **Guitar / Synth** switches the melodic source.
In **Studio > Drums**, choose **Kit: ...**, then **+ Kit** for a four-lane starting
kit. General, Rock, House, Trap and DnB kits are available; adding a kit is one
undo action and preserves other tracks. Presets and kits do not replace notes.

There are 45 read-only built-in sounds (the original 9 plus 36 new starting
sounds), including eight guitar patches and genre-oriented basses, keys, leads,
pads and percussion. Genre groups cover rock/metal, blues/funk/jazz, house/techno/
trance, hip-hop/trap/lo-fi, DnB/dubstep, pop/synthwave/disco, ambient/cinematic and
chiptune. They are synthesized starting points, not realistic acoustic libraries.
Personal patches retain their existing 32-entry limit and Save As behavior.

New parameters are appended after the original 41, for 55 total:
`instrumentType` (0 oscillators / 1 string), `stringDecay` (0.1-10 s),
`stringDamping`, `stringMute` (0-1), `stringPick` (0.05-0.95),
`driveType` (0 off / 1 overdrive / 2 distortion / 3 fuzz), `drive` (0-36 dB),
`driveTone` (200-16000 Hz), `fxMix` (0-1), `fxOutput` (0-2),
`ampBass`, `ampMid`, `ampTreble` (-12 to +12 dB), `cabinet` (0-3).
Missing new fields preserve old patches: oscillator source, drive/speaker off,
neutral EQ and unity effects output. Wire/persistence format version 1 remains
supported. Full sound snapshots, including effects, save with personal patches and
projects and replicate to observers/late joiners. Built-in updates do not rewrite
saved project snapshots. Native `openmw.synth` and `I.ProceduralSynth` are version 5;
the latter also exposes `sound(trackIndex)` (0 for the manual instrument).

Setup **-GuitarProbe** runs the disposable clean/metal two-client, history,
Stop and SQLite test. The native test helper accepts
`--bank-preview <parameters.tsv> <output.wav>`; generate its input using
`lua scripts/procedural-synth-tests/export-bank.lua <parameters.tsv> [Guitar]`.
This renders actual native patches; it is not a Studio export feature.

Design reference for the string model: Julius O. Smith, Physical Audio Signal
Processing, https://www.dsprelated.com/freebooks/pasp/Electric_Guitars.html .
The remaining transport/routing/editor milestones are tracked in ROADMAP.md.


## Native Studio transport (API 6, package 7)

Studio now compiles clips and imported MIDI into a bounded native score before
playing. One 48 kHz mono stream mixes up to 16 independent instrument/effects
lanes against one sample clock. Onsets, gate releases, overlapping same-pitch
notes, swing, loops and hat choke execute on the audio thread. Lua updates the
editor, prepares scores and handles control/network messages; a long game frame
no longer stops the sequencer or bunches its scheduled notes into a later frame.
The standalone manual synth remains an immediate instrument.

The existing Play clips / Play song / Stop controls select the native path.
BUFFER means a score is being transferred. Starting a performance normally arms
it for a shared server time 750 ms ahead. Looping clips repeat natively. Imported
MIDI retains its tempo map, sustain and note cleanup; added clips follow the MIDI
beat map. As before, Play song finishes at the song end; Loop controls repetition
of accompanying clips. Changing loop length or the Loop setting stops playback;
press Play again. Step/note/swing edits during playback prepare a replacement
score for a future bar boundary, retaining the old score until that point.
Sound and mixer edits update their independent native lanes directly.

Only the authenticated performer can upload/start/replace/stop a score. The
server validates sorted onsets, finite/bounded durations, configured lanes,
40 note-ons/sec with burst 80 (including loop boundaries), and at most 4096
outstanding gates. A score holds at most 60,000 note spans / 30 minutes, encoded
as 11-byte records (LE onset and duration in samples, lane, pitch, 7-bit velocity).
Uploads use bounded 2816-byte chunks; pending uploads expire and Stop cancels
both uploads and scheduled playback. Rejected/incomplete scores never become
listener performances. The client sends up to 32 chunks/sec, burst 8; server
limits and ownership checks apply independently.

The server caches the current compiled score and its start timestamp. Relevant
listeners, including late joiners, receive the score, instrument states and
clock anchor; they do not need the performer's MIDI file or frame-dispatched note
messages. A late join seeks to the current phase and enters on future attacks;
it does not replay historical attacks or reconstruct already-held sustained
notes. Stop, Finish, session loss and cell changes cancel future scheduled notes.
The existing session/liveness timeouts still apply to prolonged hangs/disconnects.

Clock synchronization uses RTT-filtered server echoes and several startup
samples when the first RTT is high. Native start/replacement accounts for queued
OpenAL audio; the UI uses an estimated audible position rather than the render
cursor ahead of it. Tracks within a Studio stream share exact sample positions.
Separate machines use estimated start alignment; device clock drift, driver
latency and network asymmetry are not solved by this milestone. Continuous drift
correction and audio-device loopback measurement remain future work.

Native `openmw.synth.createStudio(object)` returns a Studio with `configure`,
`set`, `noteOn`, `noteOff`, `releaseTrack`, `loadScore`, `start`, `replace`, `stop`,
`notes`, `trackPeak`, `trackVoices`, `keepAlive`, `close`, and read-only `playing`,
`position` (render cursor), `audiblePosition` (queue-compensated estimate),
`strikes`, `voices`, `peak`, `fault`, `closed`. `releaseTrack` releases its current
voices; `stop` also cancels the score. `maxUnits=128` bounds native instruments
plus streams globally; Studio lanes are allocated on the control thread and
retained for the session. No score construction, heap allocation or blocking
control mutex acquisition occurs in the render path. Each lane retains its
existing eight-voice Studio cap and independent effects. All lanes currently
feed the placed keyboard's mono spatial emitter; separate held instruments,
stereo buses and mixer sends remain planned.

Personal sound/project formats and their per-character SQLite namespaces remain
unchanged. Playback scores are transient; saved projects retain editable notes,
patterns, MIDI references, sound snapshots and mixer settings as before.
Use setup **-TimingProbe** only in the disposable fixture: it deliberately blocks
Lua for 1.5 seconds while asserting that native notes and position continue,
then exercises replacement, late listening, Stop and MIDI plus clips.


## Studio channel mixer (API 7, package 8)

Open Studio > Mixer > Mix on a track. Sound still opens the instrument editor;
the Piano tab opens the selected track's notes. The processor page provides:

- EQ bypass, 12 dB/octave high-pass (20-1000 Hz), bass shelf at 120 Hz,
  mid bell with adjustable 200-6000 Hz center (Q 0.7), and treble shelf at 6 kHz.
  Each EQ band has -18 to +18 dB gain.
- Compressor bypass, threshold (-60 to 0 dB), ratio (1:1 to 20:1), attack
  (0.1-200 ms), release (10-2000 ms) and makeup gain (0-24 dB). This is a
  feed-forward peak compressor with a 6 dB soft knee and no look-ahead.
- Post-fader track peak/RMS, compressor gain reduction, pre-limiter master peak
  and output master RMS. These are generated PCM levels before local monitor
  volume and world attenuation. Peak decay is about 300 ms; RMS averaging is
  about 150 ms. A master peak above 0 dBFS flags excess mix level.

The native C++ signal path is instrument/patch effects > channel EQ > compressor
> track level multiplied by project master > sum > existing protective tanh
limiter > spatial keyboard emitter. Moving a mixer fader no longer changes the
level entering patch effects or compression. Strong old patches can therefore
have slightly different gain staging than in earlier builds.

Mixer controls and bypass transitions are smoothed; the audio callback allocates
no strip buffers and never waits for the control mailbox. All 16 lanes stay on
the existing native Studio clock. Manual standalone synth voices retain their
existing instrument effects path.

Each project track stores an optional `mixer` snapshot. Older version-1 projects
default to bypassed EQ/compression. Project save/load and undo/redo include it;
loading a sound preset preserves it. Sound presets remain instrument-only.
The authenticated server validates and relays the settings and includes them in
late-listener snapshots. Client changes coalesce to the latest value per lane
with a bounded update budget; pending channel settings precede score commits.

Native API additions: `studio:mixer(track, values)`, `trackRms(track)`,
`trackReduction(track)`, `masterRms`, `mixPeak`, and read-only
`synth.mixerParameters`. `trackPeak` is now measured after the channel strip and
fader. Mixer table names are `eqEnabled`, `highpass`, `bass`, `mid`,
`midFrequency`, `treble`, `compEnabled`, `threshold`, `ratio`, `attack`,
`release`, `makeup`; times are milliseconds and bypass switches use 0/1.
Missing controls use native defaults; native and server bounds reject invalid
numeric states. Native synth API version 7 is required by this package.

Shared delay/reverb sends, buses, stereo panning, sidechains, brickwall limiting,
and separate physical destinations remain future mixer work.


## Two-octave keyboard and shared returns (API 8, package 9)

The instrument keyboard now spans C4-C6: 25 chromatic keys in the same width,
including the closing C. Mouse position still sets velocity and releasing outside
still releases the note. The existing physical-keyboard mapping remains C4-C5.

Click the preset name in Synth or a saved sound name in Studio to open the sound
selector. Click MIDI list in Synth or the MIDI name in Studio for the song list.
MIDI rows show only the song name; full paths remain internal for loading/search.
Both selectors support literal, case-insensitive filtering, a draggable scrollbar
and mouse-wheel scrolling. Only eight result rows are rendered at a time, even
with a 512-item catalog. Opening centers near the selection; filtering resets the
scroll position. Escape or clicking outside closes the popup. Typing a filter
cannot trigger instrument keys. Picking a sound loads it; picking a MIDI file
selects it for Play/Import. The popup closes on window rebuild, hide or Finish.

Studio > Mixer > Mix now includes post-fader Delay/Reverb sends on each lane.
Mixer > Delay / Reverb opens the shared return controls. One native delay and one
native reverb process the summed sends per Studio, rather than one pair per voice.
Old projects have zero sends and stay dry. Settings are project data, participate
in undo/redo, and replicate to listeners including late joiners.

Delay: 40-1500 ms, fractional read position, smoothed time changes, low-pass
feedback capped at 85%, bypass and return level. Moving time while playing glides
pitch. Reverb: eight damped feedback combs and four all-pass diffusers, 0.2-8 s
nominal decay, damping at 200-16000 Hz, bypass and return level. This is a basic
algorithmic mono room, not convolution or a model of a named hardware unit.

The signal path is now instrument effects > channel EQ/compression > track fader
> dry sum plus shared sends/returns > project master > protective limiter > mono
world emitter. Track meters are before master; master affects dry and wet output
together. Existing tails can continue after muting a track; Stop fades return
output over 10 ms, clears buffers and prevents queued tails from resurfacing.
No render-time buffer allocations or blocking control locks are introduced.

Native additions: mixer parameters `delaySend` / `reverbSend` (0-1),
`studio:effects(values, master)` and `delayPeak` / `reverbPeak`. Global effect
names: `delayEnabled`, `delayTime` (ms), `delayFeedback`, `delayReturn`,
`reverbEnabled`, `reverbDecay` (seconds), `reverbDamping` (Hz), `reverbReturn`.
Bypasses use 0/1; master is 0-1. Return meters are before master and spatial gain.

Late listeners receive settings and seek the current native score; delay/reverb
history is rebuilt from subsequent notes. Existing wet buffers are not transferred
across the network. Stereo output, tempo-synced delay divisions, auxiliary group
buses, automation and physical instrument routing remain later slices.


## Whole-song sound sets (package 10, native API 8 unchanged)

Previously, each new melodic MIDI part copied the manual synth's current patch;
GM program metadata was read but not used for assignment. GM percussion used
four basic families, with other notes falling back to snare.

New imports use the MIDI instrument family at the part's first note (including
program messages in separate setup tracks). Names help when no program exists;
otherwise an unidentified melodic part uses keys. Program changes later within
one part do not change its assigned Studio patch during playback. These are
approximations from our own synthesis bank, not a complete sampled GM sound set.
Six additional keys/string/organ/brass/reed/tom patches bring the built-ins to 51.
MIDI bass assignments compensate for the manual bass presets' octave-down tuning.

On Studio > Mixer, the Sound set arrows immediately apply Balanced, Rock, Metal,
Electronic, Lo-fi / Jazz, Chiptune or Ambient across existing tracks. Click the
name for the searchable/scrollable list. These are complete instrument-and-drum
arrangements; the separate + Kit button still adds four editable drum lanes.
GM toms use a pitched tom body; cymbals and other unsupported percussion remain
approximations and need more dedicated voices or sampling in a later slice.

Switching sets updates native track parameters while playback continues. It keeps
notes, timing, track identities, levels, mute/solo, EQ/compression, sends, returns
and master settings. One Undo restores the previous complete sound snapshots
(the existing project Undo stops transport). Individual sound edits mark the set
Custom. Existing saved sounds and same-file reimports are preserved; choose a set
explicitly to remap an older project. The selection and snapshots save per
character; observers receive ordinary bounded instrument-state updates. A full
32-track switch may reach listeners over multiple control-update frames.

## Player and NPC performers (package 13 / native synth API 10)

The Studio owner is the band leader: that player chooses parts, patches,
outputs and transport. Band > member destination now lists nearby players and
character-owned Studio NPCs alongside placed keyboards. Refresh instruments
refreshes that roster. Bind a player/instrument, assign tracks to the slot,
then use Invite if another invitation is needed.

Each player presses F9 to open Band / Performer. Carry the portable keyboard,
vanilla lute or vanilla drum in inventory, choose Ready for that instrument,
and Accept the leader's invitation. The leader can bind their own character and
choose Ready without a self-invitation. Decline, Not ready / holster and Leave band
are always available. An invitation only displays a notification; it never
opens a modal or takes over the observer's camera. F9/Escape closes the panel;
F8 returns to a Studio the player already owns. Ordinary camera controls remain
available with these windows closed. Self props/arm poses are hidden in first
person to avoid clipping through the camera; third person shows the performer.

Consent is connection/session scoped and expires with the session, disconnect,
death or Leave. Invitations expire after 30 seconds. Saved player targets use
native character IDs, never connection GUIDs or saved consent. Being ready
requires an actual server inventory item. Ready only supplies a stage prop while
that assigned actor output is playing; it does not equip an engine weapon.
Holstering silences the part; readying again rejoins the current song phase.
Leaving requires a fresh invitation. Unavailable destinations never fall back
to another performer or the workstation.

Create owned NPC performer makes a distinct persistent Studio NPC, owned by
the leader's character. Bind that NPC to keyboard, lute or drum. Dismiss this
owned NPC removes it and its roster entry. Other characters' performers and
ordinary game NPCs cannot be claimed by choosing a multiplayer ID or having
simulation authority. NPC ownership and stable band targets save in the server
SQLite database. NPC instruments are visual stage props, not lootable equipment.
This first pass retains ordinary NPC AI; it does not add followers, stage
blocking, combat overrides, or finger animation. Dead, missing or distant NPCs
stay silent. The compact keyboard is held; the standing keyboard remains placed.

Audio stays inside the native synth/Studio DSP: each assigned actor gets its
own spatial stream containing only its routed lanes on the common server song
clock. Lua resolves authorized actors, renders expiring bone-attached props and
runs two-link arm IK. New openmw.animation APIs setVisualAttachment,
clearVisualAttachment and visualAttachmentCount support loaded local/remote
actors with eight bounded keys and real-time expiry (0.05..2 seconds). Props
refresh without rebuilding their model each frame. They do not alter physics,
inventory, equipment or network state. Server bindings expose read-only native
character identity/health and getActorsInCell for owned-spawn recovery.

For local tests, stop the existing isolated fixture and run setup with
-PerformerStage to supply one vanilla lute and drum to Synth A/B. Existing
profiles, shared settings, projects and inventory are preserved. -PerformerProbe
also enables the disposable automated test; rerun without that flag before
normal play. Its QA removal script is never included in normal server scripts.


## Editable MIDI piano roll (package 14 / native synth API 10)

In Studio, choose a MIDI and Import (or Load your saved project). Open Piano,
select a MIDI track with the track arrows, then click Edit MIDI. This is an
explicit, undoable conversion of that part into saved note data. Its patch,
channel mix, member output and band slots stay intact. The original MIDI file
is never rewritten. Other parts remain source-backed until converted too.

- Click empty grid space to add a note. Click a note to select it; Shift-click
  adds/removes notes from the selection. Select all / Ctrl+A selects the track.
- Drag the selected notes to move their pitch/time. Drag a note's right edge
  to resize the selected gates. Preview is local; release commits one undo step
  and one native sequence update. Arrow keys nudge time/pitch.
- Copy / Ctrl+C copies selected intervals; Paste / Ctrl+V inserts them at the
  left edge of the visible time range. Duplicate / Ctrl+D copies them one grid
  step later. Delete removes the selection. Undo/redo use the existing history.
- Velocity changes selected notes, or the default for new notes if none are
  selected. Len -/+ changes the default new-note length. Note selection, view,
  snap, zoom and clipboard do not edit the saved song by themselves.
- Snap cycles 1/64, 1/32, 1/16, 1/8, 1/4 and Off. Imported notes are never snapped
  on conversion; grid-sized moves preserve their original off-grid offset.
- Zoom shows half, one, two or four bars. Use time arrows, the draggable time
  scrollbar or Shift-wheel to pan. Wheel scrolls pitch; Ctrl-wheel zooms time;
  Oct -/+ moves the pitch range. Up to 512 visible note widgets are rendered;
  zoom in when a dense view exceeds that display limit.

Play song plays the current imported/edited arrangement with its tempo map.
Select a different file and Import to replace the source arrangement. Play clips
plays the separate looping piano/drum clips. Edited MIDI parts play once on the
song timeline; they are not truncated or repeated at the 16-bar clip loop.
Original and converted parts share the same native PCM clock and physical band
routing. Live note changes use the existing scheduled bar replacement.

Save/Load stores converted notes, MIDI PPQ, source sound roles and a tempo-map
snapshot in the character's server SQLite project. An explicitly empty edited
part remains silent after load; deleting its notes never restores the source.
Once all source parts are converted, the saved arrangement can play without the
original file. Mixed projects still require that file for unconverted parts.
Sound-set cycling retains GM family/percussion roles even without the source.

Limits: 4,096 converted notes per part, 8,192 per project, 1,024 tempo changes
and a 30-minute native song. Refused conversion keeps the source part intact;
there is no silent truncation. Compact tick records bound the project payload
(ten bytes per converted note). Clip limits remain 128 notes/track and 512 total.
Source PPQ and effective sustain gates are preserved; sustain/control events are
baked into note lengths rather than exposed as editable controller lanes. The
bar grid assumes four quarter notes. Tempo-map editing, recording, arrangement
clips, automation and MIDI export are subsequent slices. Game-audio sample
instruments and the /s voice catalog browser remain planned.

The optional -EditingProbe setup flag installs a disposable two-client test in
the existing isolated fixture. It temporarily saves test projects; back up the
current database and profiles first. Rerun setup without that flag after QA.


## Quantized recording and song selection (package 15 / native synth API 11)

Selecting a different MIDI in either editor and pressing Play now imports and
plays that selection, including from Band. Playing the already loaded file
keeps its edited notes, patches and routing. Each asynchronous parse carries
its file, intent and session identity; changing selection cancels the old load.
Load restores the project selection. Fully converted saved songs can still play
when their original file is absent. The picker marks a different pending choice
as selected instead of claiming that it is the currently playing arrangement.

part (use Edit MIDI first). The recording keyboard has 25 mouse keys; musical
typing uses Z S X D C V G B H N J M comma. Oct -/+ changes the typing range.
This first recording slice uses computer/mouse input, not an external MIDI device
or microphone. Monitoring follows the track's patch, mixer and band destination;

## New Song and full-song authoring (package 16 / native synth API 11)

Open Studio > New Song. Set tempo, meter and initial length, then Create song.
The default is eight bars of 4/4 at 120 BPM, with one empty piano part. No MIDI
file is needed. New Song preserves the physical band roster while starting fresh
notes, sounds and track routing; Undo immediately restores the previous document.
Save before Finish. This remains one current Studio project per character.

Song contains the song length, meter, inclusive From/To bar loop markers and
Song loop. Add melodic parts (keys, bass, guitar, pad) or individual drum voices
(kick, snare, closed/open hat, tom). Notes opens the existing piano roll; draw,
move, resize, copy/paste or Record keyboard. Sound and Mixer choose/edit patches;
Band routes any part to a placed keyboard or consenting player/owned NPC.
Each drum part is its own synth voice; it is edited in Notes. The existing Drums
page remains the independent step-clip overlay.

Play song plays the authored arrangement rather than the selected installed MIDI
file. Explicitly selecting a MIDI file and pressing Play still imports that file.
Creating/loading/undoing a document cancels any pending file parse or selection.
Full-song parts use saved PPQ notes immediately; Edit MIDI conversion is not
needed. Saved projects reload/play without a source file. Drum sound roles,
channel processing, patches and band destinations use the existing project data.

Songs support 1-256 bars, 40-240 BPM and meters with numerator 1-12 and denominator
2/4/8/16, subject to the existing 30-minute limit. Bar lengths, piano-roll captions
and grid, visual count-in and native score replacement follow the chosen meter.
BPM changes update the constant authored tempo map. Meter changes preserve notes'
quarter-note timing. Shortening preserves later notes; they are excluded from
playback until the song is extended. Note limits remain 4,096 per part and 8,192
full-song notes per project. Up to sixteen total tracks and eight band slots.

Song loop plays only its selected bars, with the playhead mapped to their actual
song position. Gates crossing the region edges are clipped; an existing sustained
note crossing the start is retriggered for its remaining gate. Overdub finishes
at the next region boundary and releases held notes. Quantization stays within
both bounds even when a selected region is shorter than the recording grid.
Stopped recording starts at the piano-roll view with a meter-length visual
count-in. No audible metronome or latency calibration is added.

Clip bars and Clip loop remain separate four-quarter-note clips, capped at sixteen
bars. They can overlay the song as before. Scratch songs have a constant tempo
and meter, not tempo/meter automation lanes. Arrangement clips, controller editing,
MIDI export, project library/recovery, hardware input and game-audio sampling are
still planned. The optional -CompositionProbe setup flag runs disposable native
A/B tests in the established fixture; back up current DB/profiles before QA.

## Installed-game sample instruments (package 18 / native synth API 12)

within the first ten minutes. Root is the MIDI note that plays at original speed.
One-shot ignores note-off and plays to the excerpt's end; Gated follows note length
and the sound's amplitude envelope. Stop preview ends local audition. Audition
uses the instrument monitor volume and is not broadcast as chat speech.

Use sample on part changes that part's instrument while preserving its notes,
channel mixer and band output. Piano-roll notes, keyboard recording, imported MIDI
and reusable clips all use it. Sound / save preset opens the usual sound editor:
attack/release, gain, filter and insert effects still work, and Save As creates a
personal sample sound. Edit part sample copies the selected part's saved reference
into the browser for further trimming. Use synth keys selects a synthesized sound.

Save/Load stores paths, a 128-bit source-file identity, trim, root and playback
mode in the character's existing server project/preset data. Game audio never
travels with the project. Each listener resolves its own installed file; missing
or different files leave that part silent, with a local status message. Other
parts continue. Pending samples show Loading; the owner can press Play again when
ready. A listener that finishes loading during a song joins on subsequent notes.

Native decoding uses one bounded background worker and the existing FFmpeg/VFS
reader. The audio callback reads immutable 48-kHz mono PCM with independent voice
cursors and performs no file I/O, decoding or PCM allocation/reclamation. Limits:
32 cached excerpts (at most 176 MiB PCM plus bounded decode scratch), 16 queued
loads, source files at most 64 MiB, decode work limited to ten seconds per job,
and the existing 32-voice standalone / 8-voice-per-Studio-lane budgets. Typical
stereo game files are averaged to mono for physical instrument placement.

Pitch changes playback speed/duration using linear interpolation. This first pass
has no sustained sample loops, chopping, reverse, crossfades, multisample zones,
stereo sample lanes or time stretching. The file identity detects mismatches;
it is not an authentication or cryptographic integrity mechanism. Discovery is
capped at 100,000 installed sounds. Rebuild speech metadata after updating the
server catalogs with lua scripts/generate-procedural-synth-speech-catalog.lua.


## MIDI export, names and expanded editing (package 19 / native synth API 13)

Use **Export MIDI** in the Studio header to write a Standard MIDI format-1 file.
It exports the complete song, including linear notes, repeated/transposed/unmuted
linked clips, velocities, note lengths, tempo changes and authored meter. A project
containing only the older piano/drum patterns exports one active pattern cycle.
An enabled song-loop range does not crop the export. Unedited imported parts still
require their original MIDI source. Export does not stop playback or alter the song.

The result appears immediately in the MIDI song picker and is available after
reconnecting. The status message gives its full local path: studio-midi/ beside
this character's config/player_storage.bin, under the server/account/character
profile. Each export gets a new filename; earlier files are preserved. Files stay
on this computer, outside the server database. Move/copy them normally to use in
another DAW. The folder holds at most 128 exports; move older files out when full.

MIDI carries notes, tempo, names and supported original GM program hints. Your
synth patches, sample audio/settings, effects, mixer and band routes remain in the
saved Studio project. Opening exported MIDI elsewhere will use that application's
instruments. This is MIDI export, not rendered audio export. Limits: 29,000 expanded
notes and 512 KiB, plus existing playback density/duration limits. Sixteen melodic
parts use MIDI Port metadata for the final part; percussion uses MIDI channel 10.
The current importer preserves tempo but does not apply time-signature metadata.

Choose **Rename** beside a Song part or on Piano, or select a Mixer part and press
**Rename track**. Enter up to 48 bytes and use **Apply name** (or Enter); Cancel /
Escape discards the draft. Names appear across views, support Undo/Redo, save with
the project, and become MIDI track names on export. Notes, samples and routing stay
attached to the same part. Reimported names retain the usual channel/pitch suffixes.

On Drums, select a source bar and use **Duplicate to next bar**. It copies all drum
lanes, including lanes on the other page, with their velocities and rests. It
replaces the next bar, selects that bar, and grows the active clip length when
needed, up to 16 bars. Undo restores the entire operation, including clip length.
Melodic notes and reusable arrangement clips are separate from this pattern copy.

Fullscreen and window resizing now give Studio an actual larger canvas. Piano
uses the additional width for more time and the height for more pitches, retaining
readable controls at the chosen Scale. Drum steps spread across the width. Headers
stay at the edges; other Studio page bodies stay centered. Restore returns to the
previous window geometry. The Synth sound editor retains its existing fixed layout.

For disposable two-client export/rename/duplicate-bar QA use setup's -ExportProbe;
back up the latest fixture database/profiles first. Setup without that flag restores
normal interactive mode. It never needs a second fixture or a different port.

## Named project library and recovery (package 21)

Click **Projects** in the Studio header (replaces the former Load button). Each
character has up to 16 named Studio projects in the server database. Choose a name
in the searchable picker and press **Open**; selecting a name alone does not load it.
Your former single project is copied into the library automatically on first use.
The original legacy project row remains intact. Sound presets have their own list.

**Save** / **Save current** updates the currently opened named project; an unsaved
new document becomes a new entry. **Save As new** opens a name field and creates
an independent copy after **Create project copy**. To rename an existing entry,
select it, edit the name field below the picker and press **Rename project**.
**Delete project** requires **Confirm delete**; Cancel delete preserves the entry.
Deleting the active named entry keeps the open document as an unsaved copy.
Project names allow 1-64 bytes. Names may repeat; IDs distinguish picker entries.

Every 30 seconds, dirty projects produce a server recovery snapshot, including
when the editor is hidden. Autosave never replaces a named save, changes the score
or clears the unsaved indicator. The latest snapshot of each draft is updated;
only the three most recently updated drafts are retained. These snapshots may
predate a later manual save. An unfinished take must first be kept or cancelled.
At most the changes since the last acknowledged snapshot can be lost on a crash.
Recovery cannot write while disconnected; this is not an offline backup system.

Open **Projects** (or Refresh) to see recovery snapshots. **Restore draft** loads
one as an unsaved copy. Save As gives it a named library entry. Recovery includes
notes, sources/placements, sound/sample references, mixer/effects and band routes;
original imported MIDI and installed sample files are still needed where referenced.
Game audio is not copied into server storage, and MIDI exports still stay local.

Creating/importing another song, opening/restoring a document, Finish and keyboard
pickup protect unsaved work. Choose **Save and continue**, **Keep recovery and
continue**, or **Cancel**. Continuation waits for the server acknowledgement; a
failed/timed-out request retains the edits. Changes made during a pending save
remain dirty. A delayed Open response cannot overwrite newly edited music. Hide
and Escape keep the current draft/session and do not require a save choice.

The library and recovery use separate versioned character-storage rows. Stale
project revisions, unsupported stored versions and malformed documents are
rejected without replacing those rows. Projects are private to the authenticated
character, not tied to a particular keyboard or shared with listening band members.

Optional setup -LibraryProbe exercises Save/Save As/rename/delete, autosave,
guarded switching, recovery, observer isolation and restart persistence in the
usual fixture. Back up its latest DB/profiles before QA; normal setup disables it.


## Automation and MIDI controllers (package 22 / native synth API 14)

Open **Auto**, choose a part, then choose a parameter from the searchable picker.
All 55 synth parameters have lanes, including sample gain/filter/envelope settings
where applicable. Performance lanes are pitchBend (fixed +/-2 semitones), modulation
(CC1, independent 6 Hz vibrato), expression (CC11), midiVolume (CC7), pedal (CC64)
and program (zero-based 0-127). Expression and MIDI volume multiply the signal;
they do not overwrite the patch volume, track fader or local monitor setting.

- Click the graph to add a point. Drag its square to move it; right-click it to
  delete. Editing commits on release and supports Undo/Redo. The graph expands
  with the Studio window/fullscreen view.
- Linear/Step controls the interpolation leaving a point. Switches, instrument
  types and programs always step. Select a point, choose a value/time and use
  Add / update point; a different time adds another point. Delete selected removes
  that point. Values are in native parameter units; time is in quarter notes.
- Navigate with < time / time > and the one-to-sixteen 4/4-bar view picker. This
  first graph uses quarter-note timing even when the song has another meter.
  Mouse edits and captured slider changes snap to 1/64 notes. Point times imported
  from MIDI retain source PPQ timing.
- Play song/clips, choose Write while playing, and move the Auto value slider to
  capture changes at the native audible playhead. End write commits the take as
  one Undo action and queues one bar-boundary score replacement. The pass is
  heard after that replacement; this is curve capture, not live hardware MIDI
  monitoring. Stopping, changing pages/parts/parameters or saving ends the write.
  Autosave waits until a write finishes.
- Import MIDI controls explicitly replaces the selected part's supported MIDI
  lanes while preserving its synth-parameter curves. Existing projects keep their
  prior playback unless controls are imported. Channel controls include setup
  tracks; reset-all-controllers resets the supported performance lanes.
- Import controls before converting an original MIDI part if you want editable
  pedal timing: conversion then retains raw gates and the native pedal supplies
  sustain. Already edited notes keep their authored gates; importing controllers
  never rewrites those notes or shortens previously baked sustain durations.
- Follow programs is off by default. Turn it on to map program changes to the
  selected whole-song sound set's instrument families (Custom uses Balanced).
  These are the existing synth patches, not 128 sampled GM instruments. Explicit
  parameter curves override program snapshots. Sample parts keep their assigned
  sample and cannot enable program following; assigning a sample turns it off.

Curves save with each track in named projects/recovery snapshots, keeping the
existing character privacy and band output assignments. Notes, controller points
and program snapshots share the immutable native score and spatial band routing.
Audio-thread interpolation does not depend on Lua frame rate. Seek/late join,
loop/crop and live replacements chase curve values; Stop/natural completion
release deferred pedal notes and restore the editable/manual patch.

Budgets: 1,024 authored points per lane, 8,192 per project, and 8,192 compiled
control records in addition to the existing 60,000-note budget. A followed program
expands to 55 bounded patch records, so program-heavy files can reach the compiled
budget sooner. Invalid/oversized plans fail explicitly before playback.
Automation is track/song-relative; source-clip audition omits song automation.
Mixer/return automation, controller learn, external MIDI devices, variable bend
ranges and additional CC/RPN mappings remain follow-ups.

MIDI export retains supported controller/program lanes and samples linear MIDI
ramps every 1/64 note. Synth-parameter curves and sound patches stay in the Studio
project because ordinary SMF has no portable representation for those parameters.
Export still enforces its existing note/file/event budgets.

The larger Lua package also exposed socket send-buffer backpressure during
bootstrap. The server now queues bounded batches and retries refused sends, keeping
all source chunks ahead of the completion marker and character list. This fixes
package downloads without changing the multiplayer wire protocol.


## Tempo and meter maps (package 23 / native synth API 14)

Open Song -> Timing map. Choose Position by bar, or enter the zero-based quarter
note position. Set tempo adds/replaces a BPM event; Set meter adds/replaces a time
signature. The searchable Tempo points and Meter points lists select saved events
for editing/removal and fill the local tempo/meter controls. The initial effective
point cannot be removed. Applying a timing edit stops playback; press Play song
to restart. Undo/Redo restores the complete map. The main BPM control changes only
the initial tempo and preserves later changes.

Piano bar captions/lines, Arrange labels/bar snapping, song length/loop markers,
transport bar/meter/BPM and stopped-recording count-in follow the map. Meter changes
start a new bar; a change inside a bar truncates that previous bar. Notes, linked
sources/placements and automation retain their quarter-note positions; this is
not an audio time-stretch or automatic musical re-quantization. Clip source and
legacy drum/piano pattern lengths remain in quarter-note/16-step units; their
independent clip playback does not use the song map. The piano zoom caption uses
quarter notes because the number of visible bars can change as you pan.

Maps save in the existing private character project/library/recovery database.
Shortening a song retains later notes and map points for re-extension. MIDI import
reads time-signature metadata along with tempo; MIDI export writes the conductor
map through the exported song end. Complete converted/created parts can play
without their source file; unconverted source parts still need the original MIDI.
Live note/automation edits use actual tempo/meter-derived bar frames for native
replacement; a finite song too near its end keeps the previous playing score and
asks for a restart. Older clip clients retain their fixed-bar fallback.

Limits: 1,024 tempo points, 128 explicit meter changes, 1-32 beats per meter with
power-of-two denominators 1-64, 40-240 BPM for authored changes, 256 authored bars,
4,096 playback bar intervals and 30 minutes. Imported MIDI tempos retain their
original values. Future points must also stay within time/event budgets. Unsupported
maps fail without replacing the current song. Tempo events are stepped; tempo
ramps, metronome/count-in preferences and hardware MIDI input remain follow-ups.


## Arrangement selection, variations and source offsets (package 24 / API 14)

Open Song -> Arrange clips. Click a placement to select it; Shift-click adds or
removes placements on other tracks. Drag a selected body to move the selected
group in time. The same quarter-note displacement applies to every member, so
relative timing survives mixed meters; the grabbed/primary placement supplies the
bar nudge. Movement clamps together at the song origin. Right-edge dragging still
resizes only that placement. Selection is transient and clears on document/history
replacement and index-changing deletion, without altering musical data.

Selection / Tools provides Select all (both track pages), Clear, and one-bar left/
right moves. Ctrl+A selects all, Ctrl+D duplicates the selection, Delete removes
it, Left/Right nudges time and Up/Down transposes. Duplicate placement, Remove
placement, Pitch +/- and Mute placement apply to the whole selection. Duplicates
keep linked sources and appear after the entire selected span, retaining spacing.
Each group operation validates the complete project and commits as one Undo step;
capacity, pitch/time overflow and active-take failures retain the previous project.

Make unique creates a separate source for EACH selected placement, so editing a
variation in the Piano editor no longer changes its original linked copies. It
needs one free source slot per selected placement and shares the existing saved-
note budget. Copy source to selects another edited song part and copies the source
into that track's library as an independent snapshot. Then click an empty bar to
place it. The destination keeps its own sound, sample, automation, mixer and band
output. This copies note data; it does not move whole placements vertically or
create a link between different tracks. Convert unedited MIDI parts before using
them as destinations. Sources remain capped at 8 per track.

Source offset (quarters) changes where the PRIMARY placement starts within its
source, without moving the placement or changing its duration. It wraps through
that source, chases a note held at the offset with its remaining gate, and crops
at the placement end. Zero preserves the previous behavior. This is a MIDI phrase
phase control; audio sample trim remains in Samples. Offsets must stay below the
source length, so shortening a source past an existing offset is rejected.
Offsets/unique sources save in projects, named library saves and recovery; MIDI
export flattens them through the same expansion as native playback. Offset and
group edits during song playback queue the existing native bar-boundary replacement.
Legacy placements migrate to offset zero. Native synth API stays at 14.

## Recording setup and Windows MIDI (package 25 / native synth API 15)

Open Piano -> Record keyboard -> Recording setup. Choose 0, 1, 2 or 4 bars of
count-in and optionally enable Metronome with its own click level. The default is
one visual count-in bar with the click off. The native Studio clock now drives
stopped takes as well as audible clicks; count-in follows the starting meter and
tempo. Playback clicks follow the saved tempo/meter map and loop region. They
are local monitor audio, absent from the song, exported MIDI and band network.
Existing Studio monitor volume also controls this audio.

Input compensation shifts newly recorded timestamps before grid quantization;
positive milliseconds move late input earlier. It does not delay live monitoring
or change existing notes. The setting ranges from -250 to +250 ms and freezes for
the duration of a take. Start tap calibration, listen to the 120 BPM click, then
tap the Tap button or Space on successive beats. The first two beats are ignored.
Apply timing requires at least eight accepted taps and a median absolute
deviation no greater than 40 ms. The estimate measures your tapping bias plus
input/output delay; it is not automatic hardware round-trip latency measurement.

On Windows, Refresh the MIDI input list, choose a device and Connect. Select All
channels or one channel. Notes, velocity, velocity-zero note-off and sustain feed
the existing keyboard monitoring and quantized take, using native event ages so
frame polling delay is not added to capture timing. Input stays connected across all visible Studio and Synth pages. Hide/Finish
releases notes and disconnects the device; reconnect explicitly after returning. Keep/Cancel,
Undo, project saving and physical band outputs use the existing recording path.
One MIDI input is permitted per client process. Nothing connects automatically.

Count-in, click enable/level, input compensation and channel filter are local
character-profile preferences, not server musical project data. They persist
when the client exits normally; forcibly terminating the process can skip the
engine's player-storage write. Device handles, pressed keys, pedal state and
calibration sessions never persist.

The WinMM callback only copies short messages into a bounded 1,024-event queue.
Overflow, driver error, disconnect or stale input releases held notes and keeps
a partial take where possible. No audio decoding, Lua, network or disk work runs
in that callback. A driver that cannot close safely requires a client restart.
Non-Windows builds retain recording/click tools but report hardware input as
unavailable. MIDI controller/program/bend capture, clock/transport messages,
shared-source playback overdub and additional record modes remain follow-ups.
Native clock duration stays at 30 minutes including count-in; click plans allow
at most 4,096 bars and thin pulses closer than 50 ms at extreme tempos/meters.
